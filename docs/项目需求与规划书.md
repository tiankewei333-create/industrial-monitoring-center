# Industrial Monitoring Center  
# 智能工厂监控中心 · 项目需求与规划书（1 年版）

> 版本：v1.0  
> 日期：2026-09-10  
> 定位：边学边做、可运行、可对接真实数据的工厂级系统（非展厅 Demo）

## 0. 写在前面：你要做成什么样

### 0.1 正确对标方式

宝马/西门子那一类系统，本质不是「一个漂亮 3D 页面」，而是：

1. **物理世界有数据源**（PLC / 传感器 / MES）
2. **有实时数据管道**（采集 → 清洗 → 存储 → 推送）
3. **有数字孪生模型**（设备/产线/状态/告警）
4. **有可操作的可视化**（3D + 2D + KPI）
5. **有可闭环的动作**（告警、工单、权限、审计）

你 1 年要做的是：**同一套能力链路，在「一条产线 / 一个车间」规模上完整跑通**。  
这才是工厂级；全厂百万平米、全集团协同属于 3～5 年平台级工程，不放进本计划。

### 0.2 一年后的验收标准（Definition of Done）

系统必须同时满足：

| 维度 | 验收标准 |
|---|---|
| 可运行 | 本地或服务器 7×24 可持续运行，重启可恢复 |
| 可真实 | 至少对接 1 类真实或半真实工业数据源（MQTT/OPC-UA/模拟网关二选一以上） |
| 可观测 | 设备状态、温度热力图、告警、OEE 趋势可实时查看 |
| 可追溯 | 历史曲线、告警记录、操作日志可查询 |
| 可权限 | 至少区分观察者 / 运维者角色 |
| 非 Demo | 不依赖「写死假数据刷新动画」作为主路径；假数据只能作为离线开发模式 |

## 1. 项目概述

### 1.1 项目名称

**Industrial Monitoring Center（IMC）**  
中文名：智能工厂工业监控中心

### 1.2 项目愿景

为智能工厂构建一套可落地的 **数字孪生监控与运维平台**：  
以 3D 工厂孪生为空间入口，以实时设备数据为真相源，以告警与 KPI 为决策出口。

### 1.3 场景范围（Year 1）

```
Factory Workshop A（单车间）
├── Robot Arm × 2
├── CNC Machine × 2
├── Conveyor × 1
├── Sensor Nodes × N
├── Warehouse Zone × 1
└── Energy System × 1
```

**刻意不做（Year 1 Out of Scope）**

- 多工厂联邦 / 集团级指挥中心
- 完整 APS 排产优化
- 真 RTLS 人员定位硬件体系
- 全物理高精度仿真（Omniverse 级）
- 预测性维护深度学习平台（可留接口，不做完整训练闭环）

## 2. 产品需求

### 2.1 用户角色

| 角色 | 目标 | 核心能力 |
|---|---|---|
| 值班班长 | 看产线是否正常 | 3D 总览、告警、设备状态 |
| 设备工程师 | 定位异常设备 | 点选设备、趋势、热力图、历史 |
| 能源管理员 | 看能耗与异常功率 | Energy 面板、功率曲线 |
| 系统管理员 | 配置与权限 | 用户、设备台账、阈值、阈值 |

### 2.2 核心业务对象

#### 设备（Asset）

示例：`Machine001`

| 字段 | 示例 | 说明 |
|---|---|---|
| assetId | Machine001 | 唯一 ID |
| type | CNC / ROBOT / CONVEYOR / SENSOR / WAREHOUSE / ENERGY | 类型 |
| temperature | 75 ℃ | 实时温度 |
| speed | 2400 rpm | 转速/速度 |
| power | 12 kW | 功率 |
| status | RUNNING / IDLE / FAULT / OFFLINE | 状态机 |
| updatedAt | ISO8601 | 最后更新时间 |

#### 状态机（必须实现）

```
OFFLINE → IDLE → RUNNING → FAULT
                ↑___________|
```

规则建议：

- `RUNNING`：3D 蓝灯常亮
- `FAULT`：红灯闪烁 + 告警事件
- `IDLE`：灰/白色常亮
- `OFFLINE`：熄灭 + 超时告警

### 2.3 功能需求（按优先级）

#### P0（必须有，否则不算工厂级）

1. **设备台账管理**  
   增删改查设备、绑定测点、所属区域。

2. **实时数据采集与推送**  
   后端接收工业数据 → 规范化 → WebSocket/SSE 推前端。

3. **3D 车间孪生**  
   可漫游、聚焦、点选设备；选中后显示实时面板。

4. **温度热力图（GLSL）**  
   `temperature → Color Gradient Shader (Green → Yellow → Red)`。

5. **状态灯表现**  
   运行蓝灯、故障红闪（可配置频率）。

6. **告警中心**  
   阈值、触发、确认、清除、历史。

7. **时序数据存储与查询**  
   至少保存 30 天关键测点历史。

8. **基础 KPI**  
   可用性、故障次数、平均温度、功率汇总；OEE 可先做简化版。

9. **权限与审计**  
   登录、角色、关键操作日志。

10. **配置化阈值**  
    温度上限、功率上限、离线超时等可配置，不写死在代码。

#### P1（强烈建议，Year 1 后半完成）

1. 2D 工艺/平面示意图与 3D 联动  
2. 能耗看板（分设备/分时段）  
3. 维护工单（告警一键转工单，简易流程）  
4. 多语言/主题（可后置）  
5. 导出报表（CSV/PDF）  

#### P2（可做原型，不承诺生产级）

1. 简易预测（滑动窗口异常检测）  
2. 数字孪生回放（按时间轴重放状态）  
3. 移动端只读大屏  

### 2.4 3D / Shader 专项需求

#### 温度热力

- 输入：设备或表面温度标量（归一化到 0～1）
- 映射：
  - 低温：Green
  - 中温：Yellow
  - 高温：Red
- 实现：自定义 GLSL Fragment/Vertex 或 Three.js `ShaderMaterial`
- 要求：阈值阈值变化时，热力颜色实时更新（延迟 < 1s，局域网条件）

#### 设备状态灯

- RUNNING：蓝色 emissive，稳定
- FAULT：红色 emissive，1～2Hz 闪烁
- 故障恢复后自动停止闪烁并切回对应状态色

#### 场景交互

- 左键选中设备
- 双击聚焦
- 右键/按钮打开详情抽屉
- 告警设备自动高亮并支持「一键定位」

### 2.5 非功能需求

| 类别 | 指标 |
|---|---|
| 实时性 | 关键测点端到端延迟目标 ≤ 1s（同局域网） |
| 并发 | 同时在线客户端 ≥ 20 |
| 设备规模 | Year 1 支持 ≥ 50 资产、≥ 500 测点 |
| 可用性 | 单实例可用性目标 ≥ 99%（开发环境可降） |
| 安全 | 鉴权、HTTPS（部署时）、敏感配置不入库明文 |
| 性能 | 3D 场景目标 30FPS（中端笔记本） |
| 可维护 | 模块化、配置外置、日志分级、健康检查接口 |
| 可扩展 | 新设备类型通过注册表扩展，不改核心管线 |

## 3. 技术架构规划

### 3.1 推荐技术栈（学习成本与工业可用的平衡）

| 层级 | 技术 | 原因 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 工程化主流，易招人/易维护 |
| UI | Ant Design / 自研暗色工业皮肤 | 快速搭监控台 |
| 3D | Three.js + glTF + 自定义 GLSL | Web 端落地成本最低 |
| 图表 | ECharts | 工业大屏成熟 |
| 实时 | WebSocket（Socket.IO 或原生 WS） | 状态/告警推送 |
| 后端 | NestJS（Node）或 FastAPI（Python） | 二选一；建议 NestJS 与前端同语言 |
| 数据库 | PostgreSQL | 台账、用户、告警、工单 |
| 时序 | TimescaleDB 或 InfluxDB | 测点历史 |
| 消息/采集 | MQTT（Mosquitto）+ 可选 OPC-UA 网关 | 工业常见入口 |
| 缓存 | Redis | 在线状态、限流、会话 |
| 部署 | Docker Compose | 一年内可自托管 |
| 建模 | Blender → glTF | 自建简化工业资产库 |

> 说明：不对齐 Omniverse 并不丢人。宝马用 Omniverse 解决的是超大规模协同仿真；你 Year 1 的正确路径是 **Web 孪生监控闭环**。

### 3.2 逻辑架构

```
[PLC/传感器/模拟器]
        │ MQTT / OPC-UA
        ▼
[采集网关 Ingest Gateway]
        │ 标准化 Payload
        ▼
[实时服务 Realtime Service] ── WebSocket ──► [Web Console + 3D Twin]
        │
        ├─► PostgreSQL（台账/告警/权限）
        ├─► Timescale/Influx（时序）
        └─► Redis（在线状态）
```

### 3.3 标准数据协议（建议先定死）

```json
{
  "assetId": "Machine001",
  "ts": 1760000000000,
  "metrics": {
    "temperature": 75.0,
    "speed": 2400,
    "power": 12.0
  },
  "status": "RUNNING"
}
```

统一单位、统一时间戳、统一状态枚举。  
**协议稳定比 UI 漂亮更重要。**

### 3.4 模块划分

1. `imc-web`：监控前端 + 3D  
2. `imc-api`：业务 API  
3. `imc-realtime`：推送与规则引擎  
4. `imc-ingest`：MQTT/OPC 接入  
5. `imc-simulator`：产线模拟器（开发与压测）  
6. `imc-assets`：模型与贴图资源  
7. `imc-docs`：架构、运维、接口文档

## 4. 一年路线图（学习与交付并行）

原则：**每季度都有可运行增量，不只是学习笔记。**

### Q1（第 1～3 月）：地基 —— 能采、能存、能看 2D

**学习**

- TypeScript / React 工程化
- NestJS 或 FastAPI
- PostgreSQL + Redis 基础
- MQTT 基础

**交付**

- 用户登录与角色
- 设备台账 CRUD
- MQTT 模拟器持续上报 Machine001 等设备
- 实时面板（温/速/功率/状态）
- 告警规则（超温、离线）
- 基础历史曲线

**季度验收**

- 关掉模拟器 → 设备变 OFFLINE 并告警  
- 打开模拟器 → 数据恢复 RUNNING  
- 刷新页面后状态与历史仍在（证明非纯前端假数据）

### Q2（第 4～6 月）：孪生 —— 3D + Shader + 状态灯

**学习**

- Three.js 场景、相机、拾取
- glTF 工作流（Blender）
- GLSL 基础与 ShaderMaterial
- 性能优化（合并、减面、LOD 入门）

**交付**

- 单车间 3D 场景（简化但完整资产类型）
- 点选设备联动右侧详情
- 温度热力 Shader（绿→黄→红）
- 状态灯（蓝常亮 / 红闪烁）
- 告警一键定位到设备

**季度验收**

- 温度从 40→90，模型颜色连续变化  
- FAULT 时红灯闪烁且告警列表出现记录  
- 中端电脑场景稳定 ≥ 30FPS

### Q3（第 7～9 月）：工厂可用 —— KPI、权限、运维闭环

**学习**

- 时序库与保留策略
- 规则引擎进阶
- 前端大屏性能与权限模型
- Docker 多服务编排

**交付**

- OEE/可用性简化计算看板
- 能耗面板
- 告警确认/清除流程
- 简易维护工单
- 操作审计日志
- Docker Compose 一键启动
- 备份与恢复脚本

**季度验收**

- 新同事按文档 30 分钟内部署成功  
- 连续跑 72 小时无崩溃（可用模拟器压测）  
- 任意告警可追溯到设备、时间、处理人

### Q4（第 10～12 月）：工业增强 —— 真实接入与硬化

**学习**

- OPC-UA 基础或边缘网关概念
- 安全加固（鉴权、限流、配置加密）
- 可观测性（日志、指标、健康检查）
- 压测与容量评估

**交付**

- 真实/半真实数据源接入（优先 MQTT 网关；有条件再上 OPC-UA）
- 2D 平面图与 3D 联动
- 历史回放（最小可用）
- 监控大屏模式（投屏）
- 完整运维手册 + API 文档 + 架构图
- v1.0 发布候选（RC）

**年度总验收（工厂级非 Demo）**

1. 数据主路径来自接入层，而非前端写死  
2. 断线、故障、超温等异常有完整闭环  
3. 3D 热力与状态灯与真实测点一致  
4. 历史可查、权限可用、部署可复现  
5. 文档齐全，他人可接手

## 5. 学习路径（与开发任务绑定）

不要「先学完再做」。按下面顺序，学一块做一块。

| 阶段 | 必学主题 | 立刻做出的东西 |

| W1-W4 | TS + React + API | 登录页 + 设备列表 |

| W13-W18 | Three.js + 模型 | 可点选 3D 车间 |
| W19-W24 | GLSL Shader | 温度热力图 + 状态灯 |

| W41-W48 | 真实接入 + 硬化 | v1.0 |

每周建议节奏：

- 3 天开发
- 1 天学习补基础
- 1 天写文档/复盘/重构

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 过度追求效果图像素级还原 | 一年做不成闭环 | 先数据与状态机，后视觉 |
